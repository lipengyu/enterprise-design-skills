# DESIGN.md — Enterprise Application Design System

> 本文件是项目唯一的视觉与交互设计基准。所有新页面、组件和样式修改必须遵循本规范。

## 1. 设计定位

**关键词：专业、清晰、可信、高信息密度、低认知负担、可持续扩展。**

采用混合设计方向：
- **IBM Carbon**：严谨的信息架构、清晰层级、数据密集型页面。
- **Ant Design**：成熟的企业组件模式、表单与表格交互。
- **Linear**：克制的视觉装饰、快捷操作、轻量反馈。
- **Stripe**：金融数据的可读性、状态表达和指标展示。

禁止将营销网站风格直接套用到业务后台。避免大面积渐变、玻璃拟态、过度圆角、夸张阴影、无意义插画和装饰性动画。

## 2. 页面总体结构

标准后台采用：
1. 顶部全局栏：产品标识、全局搜索、帮助、通知、用户菜单。
2. 左侧导航：一级模块、二级菜单、当前页面高亮；支持折叠。
3. 主内容区：面包屑、页面标题、描述/操作区、主体内容。
4. 可选右侧上下文面板：详情、活动记录、AI 助手或属性面板。

布局要求：
- 桌面端优先，基准设计宽度 1440px。
- 主内容区应充分利用空间，避免无意义的窄容器。
- 页面标题、主要操作和关键状态应在首屏清晰可见。
- 长页面采用分区标题和合理留白；复杂工作台可使用固定工具栏。
- 不要在同一页面同时堆叠多个不同风格的卡片体系。

## 3. 设计 Token

颜色以 CSS Token 为准，业务状态颜色必须语义化使用。

### 品牌与中性色
- Primary：`#245BDB`，用于主要操作、链接、选中态。
- Text Primary：`#172B4D`。
- Text Secondary：`#5E6C84`。
- Border：`#DFE3E8`。
- Surface：`#FFFFFF`。
- Canvas：`#F5F7FA`。
- Surface Muted：`#F0F2F5`。

### 语义色
- Success：`#1F8A5B`。
- Warning：`#B7791F`。
- Danger：`#C9372C`。
- Info：`#2563EB`。
- Disabled：`#A5ADBA`。

语义色不能仅靠颜色传达，必须同时配合文字、图标或状态标签。红色只用于错误、风险和负向指标，不用于普通强调。

## 4. 字体与排版

- 中文优先使用系统 UI 字体；英文和数字优先使用 Inter、系统无衬线字体。
- 正文默认 14px；表格可使用 13–14px；辅助说明 12px。
- 页面标题 20–24px；区块标题 16px；卡片标题 14–16px。
- 正文行高 1.5–1.65；表格行高应兼顾密度和可读性。
- 金额、比例、日期等数据应使用一致的数字格式；金额建议启用等宽数字特性。
- 不要通过全局缩小字号解决信息拥挤问题，应优先调整布局和信息层级。

## 5. 间距、圆角与阴影

采用 4px 基础间距：
- 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px。
- 页面区块间距通常 24–32px。
- 表单字段间距通常 16–20px。
- 卡片内边距通常 16–24px。
- 输入框、按钮圆角 6px；卡片圆角 8px；弹窗圆角 10px。
- 默认使用边框区分区域，阴影仅用于弹层、下拉菜单和需要浮起的元素。

## 6. 组件与交互原则

- 优先复用项目已有组件库；不得为单个页面引入第二套组件体系。
- 按钮最多设置一个主按钮；次要操作使用次按钮或文本按钮。
- 删除、撤销、提交、发布等高影响操作必须有明确确认或可恢复机制。
- 所有异步操作应有加载、成功、失败状态。
- 表单必须有标签、必填标识、校验规则和明确错误提示。
- 空状态应解释原因并提供下一步操作；不能只放一个空白插画。
- Tooltip 只补充信息，不承载关键业务规则。
- 动画应短、轻、可关闭；不得影响高频操作效率。

## 7. 数据表格规范

企业应用的表格是核心工作区：
- 默认左对齐文本，金额和数值右对齐，状态居中或左对齐。
- 表头必须明确；字段过长可截断并提供 Tooltip。
- 支持分页、排序、筛选；大数据列表应提供服务端分页。
- 固定关键识别列和必要操作列；避免冻结过多列。
- 行操作优先放在最右侧，低频操作收纳到更多菜单。
- 批量操作仅在选中行后出现，并显示选中数量。
- 金额、日期、比例、空值格式必须全系统一致。
- 不以颜色作为唯一的异常识别方式；异常数据增加图标或文字说明。

## 8. 财务与金融数据规范

适用于保费、现金价值、佣金、费用分摊、会计科目、IFRS17 计量结果等：
- 金额展示必须带币种或在表头明确币种口径。
- 千分位、负数、零值、小数位规则保持一致。
- 负数建议采用 `-1,234.56`，不要混用括号负数格式。
- 百分比明确精度，例如 `12.34%`。
- 区分业务日期、会计期间、报表期间和数据批次。
- 对汇总数提供口径说明、来源或下钻入口。
- 计算结果页面应展示规则版本、数据版本、运行批次和关键参数（按权限控制）。
- 不得在前端自行计算权威财务结果；前端仅负责展示和交互，权威计算由后端完成。

## 9. 仪表盘与图表

- 首屏优先呈现 3–6 个关键指标，不要堆满 KPI 卡片。
- 每个指标明确名称、统计口径、单位、时间范围和变化基准。
- 图表标题应表达业务问题；图例、坐标轴、单位和时间范围不可缺失。
- 同一页面颜色映射必须一致，例如收入、费用、利润不可在不同图表随意换色。
- 优先使用条形图比较类别、折线图展示趋势、堆叠图展示构成。
- 避免 3D 图表、过多饼图和装饰性图表。
- 图表必须提供表格或明细下钻方式，不能成为唯一信息渠道。

## 10. 搜索、筛选与页面状态

- 常用筛选项放在首屏；低频筛选放入高级筛选。
- 明确区分“查询”“重置”“保存筛选”等动作。
- 查询条件变化后，应明确是否自动刷新；不要让用户猜测。
- URL 应尽可能保留可分享的页面状态，如筛选条件、分页和选中 Tab。
- 页面需覆盖 Loading、Empty、Error、No Permission、Partial Data 状态。

## 11. 权限、安全与审计

- 无权限操作应隐藏或禁用，并给出清晰原因；服务端仍必须执行权限校验。
- 敏感字段默认脱敏；复制、导出、下载等动作遵循权限控制。
- 重要操作应展示操作对象、影响范围和不可逆提示。
- 审批、发布、规则启停、账务处理等操作应展示操作者、时间和状态。
- 不在前端日志、URL 或错误提示中暴露密钥、完整个人信息或内部敏感数据。

## 12. 响应式与可访问性

- 桌面端优先，最低支持 1280px 宽度的完整后台体验。
- 1024px 以下允许导航折叠和表格横向滚动；不能简单压缩所有列。
- 键盘可访问：焦点状态清晰，主要操作可通过键盘完成。
- 文本与背景应保持足够对比度。
- 表单控件必须有可读标签；图标按钮必须有无障碍名称。

## 13. 深色模式

- 深色模式使用独立的 Surface、Border、Text Token，不要简单反色。
- 状态色在深色背景下需调整亮度和对比度。
- 图表颜色、阴影、分割线应单独验证。
- 若项目没有完整深色 Token，不要只给部分组件增加深色模式。

## 14. AI 功能界面

- AI 对话、Agent 执行记录、工具调用、审批结果必须区分展示。
- 显示 Agent 当前状态：待执行、执行中、等待确认、成功、失败、已取消。
- 工具调用应可展开查看输入摘要、输出摘要、耗时和错误信息；敏感内容按权限脱敏。
- 高风险操作必须人工确认，不能通过聊天气泡弱化其影响。
- AI 生成内容应标识来源、时间或可信状态；不把模型推测伪装成系统事实。
- 对话区与业务工作区应明确分区，避免聊天界面替代复杂业务表单。

## 15. 禁止事项

- 禁止每个页面自行定义主色、圆角、阴影和字号。
- 禁止无意义渐变、玻璃拟态、大面积彩色背景和夸张动效。
- 禁止使用 Emoji 代替正式业务图标。
- 禁止把所有内容都放进卡片。
- 禁止为了“现代感”牺牲表格密度、可读性和操作效率。
- 禁止前端伪造业务状态、权限状态或财务计算结果。

## 16. 页面交付检查清单

每个页面完成前逐项检查：
- [ ] 遵循全局 Token，无私自新增颜色和字号。
- [ ] 页面标题、主要操作、面包屑层级清晰。
- [ ] Loading、Empty、Error、No Permission 状态完整。
- [ ] 表格和表单具备必要校验、分页、筛选和反馈。
- [ ] 金额、比例、日期和期间口径一致。
- [ ] 权限、脱敏和高风险操作确认完整。
- [ ] 1280px 桌面宽度下布局正常。
- [ ] 没有无意义装饰、重复组件或不一致交互。
